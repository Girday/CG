# Лабораторная работа №2 — Камера и освещение

Вариант 7: тор. C++20, Vulkan, GLFW, ImGui. Работа продолжает процедурную
геометрию и преобразования первой лабораторной.

## Реализованные возможности

- Камера: положение, yaw, pitch, угол обзора; перспективная и ортографическая проекции.
- Управление камерой через ImGui и мышью/клавиатурой.
- Два тора с отдельными преобразованиями и материалами; нормали вычисляются процедурно.
- Освещение Блинн–Фонга во фрагментном шейдере: ambient, diffuse, specular.
- Направленный источник с изменяемыми направлением, цветом и интенсивностью.
- Добавление, удаление и настройка точечных источников и прожекторов.
- Затухание точечных источников и прожекторов по закону обратных квадратов.
- Внутренний и внешний углы прожектора, плавный переход на краях.
- Отдельные наборы дескрипторов сцены (`set = 0`) и модели (`set = 1`).
- Массивы источников в storage-буферах с `std430`, без фиксированного размера массива в GLSL.
- Цветные кубики источников и белые линии направления/конусов прожекторов;
  переключение видимости через интерфейс, отдельный шейдер постоянного цвета.

Выполнены базовое задание и дополнительные задания 1–4.

Снимки программы: [общая сцена](docs/scene.png),
[прожектор и его конусы](docs/spotlight.png), [материалы](docs/materials.png).

## Сборка и запуск

Нужны CMake 3.20+, компилятор C++20 и Vulkan SDK с `glslc` в PATH.
Зависимости GLFW, vk-bootstrap, Vulkan Memory Allocator и ImGui загружает CMake.

На macOS из корня репозитория:

```sh
./lab2/run-macos.sh
```

По умолчанию скрипт использует `~/VulkanSDK/1.4.321.0`.
Для другого установленного SDK задайте переменную `CG_VULKAN_SDK_ROOT`.
На macOS Vulkan работает через MoltenVK; поддерживаемый формат глубины
выбирается по возможностям физического устройства.

Общая сборка из корня репозитория:

```sh
cmake -S . -B build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug --target cg-lab2 --parallel
./build-debug/lab2/cg-lab2
```

Самостоятельная сборка из `lab2`:

```sh
cmake -S . -B build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug --parallel
./build-debug/cg-lab2
```

Для Visual Studio добавьте `--config Debug` к сборке; исполняемый файл
находится в подкаталоге `Debug`. Путь к шейдерам задаётся при конфигурации
CMake и не зависит от рабочей директории запуска.

## Управление

Панель слева содержит четыре вкладки:

| Вкладка | Параметры |
| --- | --- |
| Scene | Камера, ambient, направленный свет, видимость маркеров и конусов |
| Models | Положение, поворот, масштаб, альбедо, цвет блика и блеск каждого тора |
| Point | Добавление и удаление точечных источников, положение, цвет, интенсивность |
| Spot | Добавление и удаление прожекторов, положение, направление, цвет, интенсивность, углы |

Для движения камеры удерживайте правую кнопку мыши над сценой:
мышь меняет направление взгляда, WASD перемещают камеру, Q/E опускают/поднимают.
Кнопка `Reset camera` восстанавливает начальный ракурс.

Углы прожектора заданы как **половины угла конуса** в градусах.
Внешний угол не меньше внутреннего. При равных углах граница резкая.
Направление источника означает направление распространения лучей, от источника к сцене.
Нулевой вектор направления при передаче на GPU заменяется на `(0, 0, -1)`.

Визуализация конусов имеет настраиваемую длину и показывает угловую область,
а не конечную дальность света. Кубики и линии проверяются по буферу глубины.

## Математика

### Геометрия и камера

Параметризация тора с большим радиусом R = 1 и радиусом трубки r = 0.35:

```text
p(u,v) = ((R + r cos v) cos u, (R + r cos v) sin u, r sin v)
n(u,v) = (cos v cos u, cos v sin u, sin v)
```

Нормаль единичная и направлена наружу. Геометрия содержит 49 × 25 = 1225 вершин
и 48 × 24 × 2 = 2304 треугольника на один тор.

Матрицы хранятся по столбцам; векторы умножаются справа:

```text
M = T · Rz · Ry · Rx · S
p_clip = P · V · M · p_local
n_world = transpose(inverse(mat3(M))) · n_local
```

`V` переводит мировые координаты в систему камеры и является обратным
преобразованием её положения и ориентации. `lookAt` строит ортонормированный
базис камеры. Ось Z направлена вверх; pitch ограничен диапазоном ±89°,
чтобы направление взгляда не совпадало с вектором вверх.

В Vulkan глубина после проекции находится в диапазоне [0, 1].
Нормали после интерполяции повторно нормируются во фрагментном шейдере.
Обратная транспонированная матрица нужна при неравномерном масштабе объекта.
Масштабы в интерфейсе ограничены положительными значениями, поэтому M обратима.

### Блинн–Фонг

Для освещаемой точки x:

```text
N = normalize(normal)
L = normalize(lightPosition - x)
V = normalize(cameraPosition - x)
H = normalize(L + V)
C = ambientColor · ambientIntensity · albedo
    + Σ radiance · (albedo · max(N·L, 0)
                   + specularColor · max(N·H, 0)^shininess)
```

Произведения цветов покомпонентные. При `N·L <= 0` вклад источника равен нулю,
включая блик: свет с обратной стороны не освещает поверхность.
Чем больше shininess, тем уже блик. Ambient добавляется один раз на сцену.
Для направленного света `L` противоположен направлению распространения лучей;
его яркость не зависит от расстояния.

Для точечного источника:

```text
radiance = color · intensity / max(distance², 0.01)
```

Ограничение знаменателя защищает от сингулярности в точке источника.
За пределами расстояния 0.1 действует закон 1/d².

Для прожектора радианс дополнительно умножается на угловой вес:

```text
c = dot(-L, normalizedSpotDirection)
a = cos(innerAngle), b = cos(outerAngle)
t = clamp((c - b) / (a - b), 0, 1)
weight = t² (3 - 2t)
```

В GLSL это `smoothstep(b, a, c)`. Внутри внутреннего конуса вес равен 1,
снаружи внешнего — 0; между ними переход плавный. Равные углы обрабатываются
отдельно через `step`, чтобы избежать деления на ноль.

## Передача данных на GPU

| Set / binding | Ресурс | Данные |
| --- | --- | --- |
| 0 / 0 | Uniform, std140 | View-projection, позиция камеры, ambient, направленный свет, количество источников |
| 0 / 1 | Storage, std430 | Массив PointLight |
| 0 / 2 | Storage, std430 | Массив SpotLight |
| 1 / 0 | Uniform, std140 | Матрица модели, альбедо, цвет и степень блика, переключатель цвета вершин |

Размеры структур C++: сцена — 144 байта, модель — 112, точечный источник — 32,
прожектор — 48. Поля источников упакованы в vec4, размеры и ключевые смещения
проверяются `static_assert`. Обычный bool напрямую в GPU-структуры не передаётся.

Источники хранятся на CPU в `std::vector`. Если места в SSBO не хватает,
`ensureCapacity` создаёт больший буфер и обновляется дескриптор.
Фиксированного лимита в шейдере нет; объём ограничен памятью и лимитами устройства.
Даже для пустого списка выделяется непустой буфер, а цикл использует число 0.

`prepare()` ждёт fence единственного кадра в полёте. Только после этого,
в начале `render()`, обновляются данные и при необходимости пересоздаются буферы.
Поэтому GPU не читает память одновременно с её изменением или уничтожением.

## Структура программы

- `source/main.cpp` — окно GLFW и главный цикл.
- `source/graphics_internal.cpp` — Vulkan, swapchain, depth buffer, синхронизация и ImGui.
- `source/application.cpp` — вызовы функций сцены из основного цикла.
- `source/scene.cpp` — ресурсы, дескрипторы, конвейеры, интерфейс и команды отрисовки.
  `objectModel` строит M; `updateUniforms` передаёт данные на GPU;
  `buildConeLines` генерирует линии прожекторов; `createMarkerGeometry` создаёт кубики.
- `source/torus.cpp` — процедурные вершины, нормали и индексы тора.
- `source/math3d.hpp`, `source/lighting_math.hpp` — матрицы и вспомогательная математика.
- `shaders/torus.vert` — преобразования вершин и нормалей.
- `shaders/torus.frag` — Блинн–Фонг, затухание, мягкие края прожекторов.
- `shaders/marker.vert`, `shaders/marker.frag` — маркеры постоянного цвета.

## Проверка

После общей сборки:

```sh
cmake --build build-debug --parallel
ctest --test-dir build-debug --output-on-failure
```

Проверяются геометрия и нормали тора, ориентация треугольников, преобразования,
глубина Vulkan, перевод позиции камеры в начало координат, закон 1/d²,
переход на краях прожектора и случай равных углов.

Прогон на macOS с окружением Vulkan SDK:

```sh
CG_SMOKE_RESIZE=1 CG_SMOKE_LIGHTS=1 ./build-debug/lab2/cg-lab2
```

Программа изменяет размер окна, очищает списки, увеличивает число источников до
65 точечных и 25 прожекторов, снова удаляет их, проверяет равные углы и нулевое
направление, меняет проекцию и автоматически закрывается через 150 кадров.
При обычном запуске эти действия отключены. Включены validation layers и debug messenger.

Проверено на macOS/MoltenVK: сборка, три теста корневого проекта,
прогон с изменением числа источников и размера окна, интерфейс добавления источников
и визуализация конусов. Ошибок валидации в проверенном прогоне нет.

Реализована сцена с управляемой камерой и освещением Блинн–Фонга.
